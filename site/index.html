The REAPER tools I built because my own sessions were slow.

A twelve-script speed layer and a set of dockable apps for organising tracks, repairing folders, printing stems and exporting MIDI. Every one of them replaced a custom action of mine that was quietly doing the wrong thing — centring pans, disarming the session, dropping markers on the wrong grid. Free, MIT, installed from inside REAPER.

02

Why these exist

This started as a bad afternoon, not a product plan. Fourteen custom actions I had been pressing for years were read line by line against REAPER 7.77. Nine of them were doing something I had not asked for.

01

A key that centred every pan

The record-arm chain ran _XENAKIOS_PANTRACKSCENTER. Every press quietly reset the pan on every armed track.

02

A key that disarmed 452 tracks

Duplicate Track cleared record-arm across the whole project and never put it back. On the live rig that is the entire record setup, gone, with nothing on screen.

03

Watchdogs that had never fired

GetProjectStateChangeCount does not move when you insert, rename or delete a track. Measured: it sat on 8 through all three.

04

Two apps that could kill REAPER

Both held a MediaTrack* after the track was deleted and read it every frame. Lua's pcall cannot catch that fault. The host process just dies.

03

Install

One repository URL, pasted into ReaPack. Updates arrive the same way everything else in REAPER does.

ReaPack

In REAPER: Extensions → ReaPack → Import repositories… and paste this line.

https://github.com/jasonzacmusic/nathaniel-tools/raw/main/index.xml
ReaImGui

Required. The five windowed apps will not open without it. Install it from ReaPack's default repositories, then restart REAPER.

SWS

Optional. Nothing in the suite depends on it — the folder work is deliberately built without _SWS_UNFOLDER, which does not exist on every install.

Licence

MIT. Read it, fork it, take the bits you want. The free core stays free.

Where this actually stands

The repository is public and the index resolves. Paste the line above and ReaPack will find the whole suite — the twelve speed-layer scripts, the windowed apps, and the JSFX that StageRig's note handling runs on.

What is not done: the suite is not yet listed at reapack.com/repos and the flagship scripts have not been through ReaTeam review, so for now you have to import the URL by hand rather than finding it in ReaPack's default browser. The parts of the suite that are reviewed but not yet exercised end to end are listed in the ledger.
