Track Settings Transfer

Pro Tools' Import Session Data, for REAPER, across every open tab and in both directions. Copy FX, volume, pan and sends onto matching tracks — or build the tracks that are missing.

Shipping 1.0.0 apps/Track Settings Transfer.lua Requires ReaImGui Dockable

The problem

Choosing one session and importing from another doesn't work, while vice versa works.

Jason, describing a bug that turned out to be exactly what it sounded like

The underlying need is older than the bug. You have a template, or last week's session, or the same song at a different tempo, and the routing and the chains you want are sitting in a tab two clicks away. REAPER's answer is to open both, select carefully, and copy things across one at a time. Pro Tools has had a dialog for this since the nineties.

Why one direction looked broken

Picking a new From project correctly removed it from the To list — nothing may be its own target. But nothing ever took its place. So swapping A→B into B→A left zero targets ticked, the app cleared its focus, and the entire track list vanished behind the placeholder text “Select a target project above.”

One direction therefore looked perfectly fine and the other looked completely broken, which is precisely how it was reported. Nothing was ever wrong with the transfer engine — you simply could not get to it.

A swap is now a swap: promote a target to source and the old source takes its place as target. There is also a ⟷ Swap button, so reversing direction is one click rather than two selections in the right order.

The fix, and the crash underneath it

REAPER frees both MediaTrack* and ReaProject* the instant a track is deleted or a tab is closed. This app's whole job is holding two projects in mind at once, which makes it the one most likely to be looking at something that no longer exists.

So the UI stores no pointers at all. Identity is GetTrackGUID, which survives delete, undo, reorder and save-reload. Every project pointer passes ValidatePtr2(0, p, "ReaProject*") and every track pointer ValidatePtr2(proj, t, "MediaTrack*") before it touches an API. Closing a tab mid-transfer is handled: the app drops that target, re-picks a focus, and says so in the log instead of dying.

Your per-track include, attribute and remap choices are keyed by GUID too, so when the row list rebuilds itself, your decisions survive the rebuild.

What it does

  • Match modeCopy FX, volume, pan and sends onto same-named tracks. Exact matches first, then similar names — flagged as such, never silently.
  • Build modeWhere a source track has no match, create it: name, colour, FX, volume, pan, folder position, then rebuild the sends.
  • Manual remapPoint any source track at any target track when the names disagree.
  • Per-track controlChoose which attributes travel, track by track.
  • Fan-outTick several targets and transfer to all of them in one pass.
  • PreviewShows exactly what would change and changes nothing.
  • UndoOne undo point per target project.
  • Drag-paintContiguous mouse-drag select and deselect. This app is where that behaviour was written.
What it will not do

It never copies automation. Envelope data is the one thing where a wrong guess is expensive and hard to notice, so it is out of scope by design rather than by omission.

Build mode used to be able to leave an unclosed folder behind. The folder depths it writes are now normalised, using the same arithmetic as Folders & Flow.

Install

In REAPER: Extensions → ReaPack → Import repositories…

https://github.com/jasonzacmusic/nathaniel-tools/raw/main/index.xml

Then Actions → Show action list, filter for Nathaniel Tools, and run Script: Nathaniel Tools Track Settings Transfer. Open the projects you want to move settings between as tabs first.

Changelog

  • 1.0.0 First public release
    • Direction swap fixed: promoting a target to source hands the target slot to the old source. Added a one-click Swap button.
    • Crash hardened: no pointers stored anywhere in the UI, GUID identity throughout, both project and track pointers validated before use, tab closure handled.
    • Auto-sync now actually fires. It was built on GetProjectStateChangeCount, which does not move on track changes, so it had never fired once.
    • Build mode no longer leaves an unclosed folder.
