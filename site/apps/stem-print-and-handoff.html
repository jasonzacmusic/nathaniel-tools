Stem Print & Handoff

Print stems the way the person receiving them wants them — pre-fader, pan-centred, at the project's own rate and depth — into a clean mirror project, and put your session back exactly as it was.

Shipping 1.0.0 apps/Stem Print and Handoff.lua Requires ReaImGui Dockable

The problem

Can you resend these? The kick is way hot, and half of them have your reverb printed on.

The email this app exists to stop receiving

Stems fail for boring reasons. A fader was riding when you rendered. A pan was left where the mix wanted it, so the mixer inherits your decision and cannot undo it. The reverb went down with the source. Or the receiving engineer does not own the plugin you printed through, so the file he gets is not the file you heard.

Doing it properly by hand means writing down every fader and pan, zeroing them, rendering, then putting them all back. On a large session that is twenty minutes of clerical work with a real chance of an error you will not notice until the mix comes back wrong.

The fix

The app saves the state it is about to change, prints, and restores — the whole thing wrapped in one undo point. Volumes go to unity and pans to centre for the print, and the mirror project re-applies your real values, so nothing about your balance is lost; it is simply moved to where the mixer can change it.

The printed WAVs land in a new project tab that mirrors your names, colours and folder structure with no plugins on anything. That tab is the handoff. Your working session is not altered.

Four print modes

  • RawNo inserts at all. Clean multitracks, exactly as recorded.
  • Inserts onlyInsert FX baked in, reverb and delay sends excluded. The dry stem.
  • Fully wetEach stem printed in isolation including its own reverb and delay returns.
  • Front-endThrough the first insert only — the mic preamp, the channel strip, the thing you would have printed on the way in.

And two things next to it

  • Mark foldersUppercase every folder and parent track name, so the Render Matrix targets your buses cleanly instead of guessing.
  • Plugin-free cloneDuplicate the project into a new tab with names, colours, routing and folders intact and every plugin removed — for someone who has your media but not your licences.

The crash that was hiding in the restore

This app had the same dangling-pointer bug as Palette & Look, and a worse version of it.

It captures every track's volume and pan, sets them for the print, renders — which takes minutes — and then restores. The restore pass wrote through pointers captured before the render. Delete a track during those minutes and it wrote through freed memory. And because that pass ran outside the error handler, a fault part-way through would leave the remainder of the session stuck at unity gain and centre pan, silently, with the log showing a completed render.

Snapshots now key on GUID and are re-resolved after the render. A track that genuinely vanished is skipped and named in the log rather than written through.

There is a reason nobody ever hit this: the app had never been registered as a REAPER action. It has, in effect, never been run. That is now fixed, and it is also why the honesty note below says what it says.

What is not proven

The crash safety and the restore path have been tested. The render pass itself has not been verified against a real multi-minute print — the code is reviewed line by line and correct by construction, but nobody has yet sat through a full stem print of a real session and checked every file that came out. Until someone has, treat the first print as a test print.

Gain matching is not built. Levelling the printed stems against each other is designed and queued, not written.

Install

In REAPER: Extensions → ReaPack → Import repositories…

https://github.com/jasonzacmusic/nathaniel-tools/raw/main/index.xml

Then Actions → Show action list, filter for Nathaniel Tools, and run Script: Nathaniel Tools Stem Print & Handoff. Read the honesty note above before your first real print.

Changelog

  • 1.0.0 First public release
    • Registered as a REAPER action for the first time. It had never been.
    • Crash hardened: volume and pan snapshots key on GUID and are re-resolved after the render; vanished tracks are skipped and reported, not written through.
    • The restore pass moved inside the error handler, so a failure mid-restore can no longer leave the session at unity gain and centre pan.
    • Change detection rebuilt on a track-list signature.
