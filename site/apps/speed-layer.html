Green · twelve scripts

The speed layer

Twelve keys I press hundreds of times a day. They used to be custom actions. Nine of the twelve were doing something I had not asked for, and I had been pressing them for years without knowing.

Shipping 1.0.0 Nathaniel Tools/ — 12 scripts No ReaImGui needed Key bindings included

The problem

Solo selected doesn't work. Record toggle doesn't work at all. And the tempo one is very tough to lock.

Jason, listing complaints that turned out to have three completely different causes

A REAPER custom action is a list of command IDs run in order. It is a genuinely good feature and it has one property that makes it dangerous over a decade of use: nothing tells you what a step does. A step you added in 2019 because a forum post recommended it will still be there in 2026, still running, still flipping something you have forgotten about.

So all fourteen of mine were read line by line, every numeric command ID resolved to its real name with CF_GetCommandText, and the results were worse than I expected.

Why they are scripts and not fixed custom actions

Because a custom action cannot be fixed. This is the single most useful thing the whole project discovered, and it is not documented anywhere:

Importing a .ReaperKeyMap whose ACT line has the same step count as an existing action of the same name is a complete no-op — REAPER silently ignores it. Importing one with a different step count creates a brand new action called “Name (2)” with a fresh GUID, and leaves the original untouched and still bound.

KEY lines always merge correctly. ACT lines never modify. So there is no path from a broken custom action to a fixed one — you can only replace it with a script and move the key. That decision is why this suite is scripts all the way down, and it is written up in full on why these exist.

The keys

Non-traditional on purpose — single unmodified letters for the things pressed most, so the left hand never leaves the keyboard. Three of them also answer to MIDI CC, because the controller is closer than the keyboard when tracking.

  • ASolo Focus — exclusive solo, follows item selection when there is one, press again to clear.
  • Shift ARecord Arm Toggle — exclusive arm on the selection, press again to disarm everything. Also Cmd Opt Ctrl U, and MIDI CC 75.
  • NumPad 6FX Float Toggle — genuine XOR float of FX 1 across the selected tracks.
  • Shift FFX Open / Close All — one unified decision across every FX on the selection. Also MIDI CC 76.
  • N  /  BRegion Next / Previous — no global preferences touched. Previous snaps to the current region's start first.
  • MMarker at Bar — the true measure boundary from TimeMap_GetMeasureInfo, integer measures, no float drift. Uses the play cursor while playing. Also MIDI CC 23.
  • Cmd Shift TTempo at Bar — inserts or edits a tempo and time-signature marker welded to the bar line.
  • Shift Ctrl MMIDI Render — builds a time selection only if there is not one, prefers selected items, falls back to the project extent, then exports.
  • Cmd Ctrl VFlush Paste — clear, paste, strip envelopes, save silently. Never opens Save As.
  • Shift DDuplicate Track — same FX, routing, name and colour; no items, no automation; armed and ready. The rest of the session keeps its arm state.
  • EUnsolo & Unselect — the panic key. Clears solo, record-arm, track and item selection, and the time selection.
What is not proven

Three of these open a modal dialog, which means they cannot be driven by an automated harness. They have been verified by code review, not by hand: the ⌘⇧T tempo input box, ⇧⌃M MIDI Render against action 40849, and ⌘⌃V Flush Paste in a real saved project — where the pass condition is that no dialog appears at all.

Everything else in the table above is covered by the harness, which builds a scratch project in its own tab and closes it afterwards.

Changelog

  • 1.0.0 First public release
    • All twelve custom actions replaced with scripts, each with its root cause documented at the top of the file.
    • Duplicate Track no longer disarms the whole project — arm state is snapshotted by GUID and restored.
    • Solo Focus no longer moves the edit cursor to the mouse and starts playback. The flag is at the top of the file if you want it back.
    • Flush Paste guards on the project having a file on disk, so it can no longer pop the Save As dialog it exists to remove.
    • Tempo at Bar reads tempo from TimeMap_GetMeasureInfo after TimeMap_GetDividedBpmAtTime was measured to return the project-start tempo regardless of position.
