Folders & Flow

Every folder operation REAPER makes awkward — take one track out, fix wrong nesting, dissolve without deleting, move a whole subtree — done on nesting levels, so the arithmetic cannot come out wrong.

Shipping 1.0.0 NPH/NPH_Folders and Flow.lua Requires ReaImGui No SWS dependency

The problem

I dragged one track out of a folder and now everything below it is inside something else.

The failure mode this app exists to remove

REAPER does not store folders as a tree. It stores an integer per track, I_FOLDERDEPTH: 1 opens a folder, 0 continues, and a negative number closes as many folders as its magnitude. The structure you see in the track panel is the running sum of that column.

Which means every folder script that edits depths in place has the same failure: a local change that looks correct leaves the arithmetic unbalanced further down. The folder never closes, REAPER silently swallows the rest of the session into it, and there is no error — just a session that is now shaped wrong.

The fix

This app never edits I_FOLDERDEPTH. It converts the depth column into nesting levels, performs the edit on the levels, then regenerates every depth in the project from the levels it just computed.

The distinction matters more than it sounds. Depths are relative and only make sense as a running total, so a local edit has non-local consequences. Levels are absolute per track, so an edit is exactly as local as it looks. The regenerated depth column always balances — it is not possible for this app to leave a folder hanging open, regardless of what you ask it to do.

The arithmetic lives in NPH/lib/nph_hierarchy.lua and is covered by 31 checks that run in plain Lua with REAPER nowhere in sight: 

$ lua tests/hierarchy_test.lua
31 passed, 0 failed

A real bug those tests caught

Building a folder from a ticked selection originally incremented the child levels relatively. On tracks that were already nested, the sanitiser then clamped inconsistently and the new folder quietly swallowed everything after it — the exact bug the whole design was meant to make unreachable, arriving through the front door.

The fix shifts the children so the shallowest one sits exactly one level below the new parent, preserving their relative nesting, and explicitly pops everything after the range back out to the parent's level. There is a regression test for it, and it runs on every push.

What it does

  • RepairRecompute the whole folder column from levels. Fixes a session whose nesting has already gone wrong.
  • Make folderTurn the ticked tracks into a folder, correctly, whatever their existing nesting.
  • Indent / outdentPromote or demote a track and everything underneath it.
  • Remove from folderTake a single track out without dragging anything.
  • DissolveRemove the folder, promote the children. Nothing is deleted.
  • Move subtreeMove a whole folder, children and all, up or down.
  • IsolateFocus one folder and get the rest of the session out of the way.
  • Auto-groupBuild folders from track names — adjacent tracks sharing a first word become a folder.
  • Drag-paintContiguous mouse-drag select and deselect down the list.
Built without SWS on purpose

_SWS_UNFOLDER and _SWS_MOVETRACKUP / _SWS_MOVETRACKDOWN are not present on every SWS install — they are absent on the machine this was written on. Rather than depend on actions that may not exist, all of it is implemented in the hierarchy library.

Your existing folder shortcuts are untouched: F still runs _SWS_MAKEFOLDER, ` still runs 1042 41665.

Install

In REAPER: Extensions → ReaPack → Import repositories…

https://github.com/jasonzacmusic/nph-reaper-suite/raw/main/index.xml

Then Actions → Show action list, filter for NPH, and run Script: NPH Folders & Flow. It opens dockable; drag it into a docker once and REAPER remembers.
