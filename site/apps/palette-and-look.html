Palette & Look

Colour and name tracks from meaning — a rule table you write once, a synonym layer that catches everything you did not think of, and structure it works out for itself.

Shipping 1.0.0 apps/Palette and Look.lua Requires ReaImGui Dockable

The problem

It crashes when I delete or modify tracks.

Jason, reporting the bug that started the audit

That was the headline complaint, and it was real, guaranteed, and worse than it sounded. But the reason to open this app in the first place is duller and more constant: a forty-track session takes twenty minutes to colour and name by hand, you do it slightly differently every time, and three weeks later you still cannot find the guitars at a glance.

REAPER's own answer is SWS Auto Color, which matches on a filter string and stops there. It has no idea that Gtr Dist L, OD Rhythm and Les Paul are all the same instrument, and no idea which of your tracks is a bus and which is a genuine FX return.

The fix

Three layers, evaluated in order, so the specific always beats the general:

  1. My rules. An ordered filter→colour table, like SWS Auto Color but with real match modes — contains, word, starts, exact, Lua pattern, role — plus live auto-apply and a one-click import of your existing sws-autocoloricon.ini, so nothing you already built is lost.
  2. Families. A synonym-aware fallback. The three guitar names above all resolve to guitar without you writing a rule for any of them.
  3. Structure. Folders, buses and true FX returns — detected from the receives and the plugins actually on the chain, not from what the track happens to be called.

Markers and regions are coloured from the same rule table, so the timeline and the track panel agree with each other. Naming works the same way: rename from the items on a track, name and colour in one pass, number a selection, apply a palette or a gradient, shade or saturate what is already there. One undo point per action.

The crash, and what it really was

The track list stored REAPER's raw MediaTrack* and read it again on every frame to draw the colour swatches. REAPER frees that pointer the instant you delete a track. Deleting, undoing or reordering with the window open handed a dangling pointer straight into REAPER's C++ and killed the application, taking any unsaved project with it.

The draw loop was wrapped in pcall, which looks protective and is not: Lua cannot catch a native memory fault. It was false comfort.

Rows now key on the track's GUID, which survives delete, undo, reorder and reload. The pointer is resolved and validated with ValidatePtr2 immediately before each use and never held across a frame. This was proved live rather than reasoned about: with the window open on the Tracks tab, a track was deleted through the API. The row rendered as a red (deleted) tombstone and REAPER kept running.

What it does

  • RulesOrdered filter→colour table with six match modes, live auto-apply, and import from sws-autocoloricon.ini.
  • FamiliesSynonym-aware instrument fallback for anything your rules missed.
  • StructureFolders, buses and real FX returns detected from routing and FX chains.
  • NamingRename from items, name and colour together, numbering, prefixes.
  • PalettesThe theme-adjuster palettes plus your own, gradients, shade and saturate.
  • MarkersMarkers and regions coloured by the same rules as the tracks.
  • Live watcherWatches the track list and applies rules to tracks as they appear.
  • ExportWrites your rule table back out to SWS format.
Not yet exercised

The crash safety and the change watchdog were verified live. Several surfaces have not been: name-from-items, name-and-colour, numbering, the Palettes tab, the Tools tab, the Tracks tab's Now→Want flow, the live watcher, docking and the SWS export. They are written and they compile; they have not been run through a real session end to end.

The contiguous drag-paint selection that every app in the suite is supposed to have exists in Track Settings Transfer and has not been retrofitted here yet.

Install

In REAPER: Extensions → ReaPack → Import repositories…

https://github.com/jasonzacmusic/nph-reaper-suite/raw/main/index.xml

Then Actions → Show action list, filter for NPH, and run Script: NPH Palette & Look. It opens dockable; drag it into a docker once and REAPER remembers.
